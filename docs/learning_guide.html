1. The one-sentence mental model

Every algorithm in this repo solves the same tiny decision: once per time step, pick a single number α (a “bid coefficient”); then bid α × pValue on every ad opportunity that step. Everything else — RL, LP, transformers — is just different machinery for choosing α well under a budget and a cost-per-acquisition (CPA) constraint.

Before any code, the whole problem is: “how aggressive should I bid right now, given how much budget and time I have left, and how the market is behaving?”

3. How a trained model actually bids (IQL)

The most important file to internalize — bidding_train_env/strategy/iql_bidding_strategy.py:

bidding(timeStep, pValues, ..., history...):
    1. rebuild the SAME 16-dim state from live history   (lines 46–92)
    2. normalize it with the saved normalize_dict         (lines 97–98)
    3. alpha = self.model(state)                          (line 101)  ← the learned policy
    4. bids = alpha * pValues                             (line 103)
    return bids
The single most important concept: step 1 must reconstruct the exact same features the training data used (§2), or the model sees a different input distribution than it trained on. Compare bidding() lines 46–92 against train_data_generator.py lines 100–118 — that train/inference feature parity is where bid agents most often silently break.
more: why it's α × pValue and not a raw bid

The agent never predicts a price directly. It predicts one multiplier on value. An opportunity worth twice as much (double pValue) automatically gets double the bid, so a single scalar paces spend across thousands of heterogeneous opportunities. The learning problem collapses from “bid on each impression” to “set one knob per step” — which is why a 16→1 MLP suffices.

4. The algorithm families (in learning order)

Start simple, then add one idea at a time. Every offline-RL method here exists to solve one problem: the dataset only shows certain actions, so a naive learner overestimates the value of actions it never saw (out-of-distribution / distributional shift). Each method is a different fix.

A. Heuristics / control no learning

Abid — fixed bid rate
A constant α for the whole episode. The baseline floor every other method is measured against.
PID — control loop
Nudges α up/down to track a target spend/CPA, like a thermostat. simul_bidding_env/strategy/pid_bidding_strategy.py. The cleanest way to understand “pacing” without any ML.

B. Optimization

OnlineLP — linear programming
Treats each tick as a knapsack/LP: given predicted opportunity values and costs, solve for the bidding that maximizes value under budget. Reads the raw CSVs to fit, not the RL transitions. run/run_onlinelp.py + baseline/onlineLp/.

C. Offline RL the heart of the repo

BC (Behavior Cloning) — the reference point
Pure supervised learning: regress α from state, imitating the data. No reward, no value function. Start here; everything else is “BC + something.”
IQL (Implicit Q-Learning)
Learns a value function without ever querying unseen actions: a V-net via expectile regression, twin Q-nets, and an actor via advantage-weighted regression. See §5 for the full breakdown. baseline/iql/iql.py.
CQL (Conservative Q-Learning)
Adds a term that pushes down Q-values on out-of-distribution actions, so the policy can't chase overestimated phantom rewards. “Be pessimistic about what you haven't seen.”
BCQ (Batch-Constrained Q-learning)
Constrains the policy to stay near actions actually present in the data, via a generative action model. Was the slowest to train here (~71 min).
TD3+BC
Standard actor-critic (TD3) plus a behavior-cloning regularizer, so the actor maximizes Q while staying close to the data. The “minimal change to online RL that makes it work offline.”

D. Sequence modeling

Decision Transformer
Reframes control as sequence prediction: feed (return-to-go, state, action) tokens and autoregressively predict the next action. No value function at all. baseline/dt/. In our runs it overspent and got penalized — a good case study in how return-conditioning can misbehave.
Suggested path: Abid → PID → BC → IQL → (CQL, BCQ, TD3+BC) → OnlineLP → DT.
5. IQL deep dive — the three losses

IQL trains three networks together (baseline/iql/iql.py, method step()). The trick: never evaluate Q on an action the policy invents — only on actions from the data.

1. Value loss — expectile regression (calc_value_loss)

Fit V(s) to an upper expectile (τ=0.7) of Q(s,a) over dataset actions. The asymmetric loss weights positive errors more, so V approximates max Q without ever maximizing over actions (which would query OOD actions).

weight = τ if (Q − V) > 0 else (1 − τ)
loss   = weight · (Q − V)²
2. Q loss — ordinary TD, but bootstrapped on V (calc_q_loss) 
target = reward + γ · (1 − done) · V(next_state)
loss   = (Q(s,a) − target)²        # twin critics, take the min

Because the bootstrap uses V(next_state) (not max_a Q), the target is always computed from in-distribution quantities.

3. Policy loss — advantage-weighted regression (calc_policy_loss) 
advantage = Q(s,a) − V(s)
weight    = min(exp(advantage · temperature), 100)
loss      = −(weight · log π(a|s)).mean()

This is weighted behavior cloning: imitate dataset actions, but upweight those that beat the value baseline. The policy stays close to the data (safe offline) while leaning toward higher-advantage actions. At inference it returns the mean action, clamped ≥ 0 (forward()).

Hyperparameters in this repo: γ=0.99, τ(tau)=0.01, expectile=0.7, temperature=3.0, three Adam optimizers at 1e-4, 20000 steps, batch 100.

7. How evaluation works (two harnesses)

Offline — single advertiser replay

run/run_evaluate.py: one advertiser replays period-7.csv; your agent bids against the recorded leastWinningCost. Win if bid ≥ leastWinningCost; conversions are binomial(pValue).

score = penalty · reward
penalty = (cpa_constraint / cpa)²   if cpa > cpa_constraint   else 1
As shipped it is low-signal. It instantiates the agent at budget=100, cpa=2, so expected conversions < 1 → scores ≈ 0 for everyone. Good for understanding the scoring formula, not for ranking. See docs/report.md.

Online — the full 48-agent simulator

Root main_test.py → run/run_test.py: your agent competes against 47 other agents in the real environment.

more: the auction loop to trace
  • simul_bidding_env/Controller/Controller.py — assembles the agent field + environment.
  • BiddingEnv.simulate_ad_bidding — the GSP auction: top bidders win slots, pay ~the next bid, then win → expose → convert.
  • the adjust_over_cost loop — drops an agent's bids when it would overspend, then re-runs the auction; this is how the budget constraint is enforced mid-auction.
The per-run analysis_info (budget_used, cpa_exceedance, win_pv_ratio) is your diagnostic dashboard — it's how we explained why DT scored low (spent 100% of budget, blew the CPA constraint → heavy penalty).
8. Hands-on exercises
  1. Trace one bid: print alpha in iql_bidding_strategy.bidding() and run the offline eval — watch α change as budget depletes.
  2. Break feature parity: zero out one state feature in bidding() and see the score move — proves §3's point.
  3. Compare losses: read calc_value_loss/calc_policy_loss/calc_q_loss in iql.py and map each to the MDP in §2.
  4. Diff two algorithms: open baseline/iql/iql.py vs baseline/td3_bc/ and find the one idea that differs (the BC regularizer).
  5. Re-run with a tweak: flip the reward → reward_continuous toggle in run_iql.py, retrain, re-eval, compare.
9. Glossary
pValueP(conversion | exposed); the predicted value of an opportunity.
α / bid coefficientthe single action; scales pValue into a bid.
GSPGeneralized Second Price auction; winner pays ~the next-highest bid.
leastWinningCostthe price floor to win (4th-highest bid for 3 slots).
CPAcost per acquisition; the constraint the penalty enforces.
Offline RL / distributional shiftlearning from fixed logs; the core difficulty every RL baseline here is engineered around.
